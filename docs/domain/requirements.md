# Requirements

## 1. 프로젝트 목적

해당 프로젝트는 포인트를 통해 커피를 주문하는 서비스를 구현한다.

## 2. 주요 기능

### 메뉴

- 상품 조회
- 상품 재고 관리

### 주문

- 주문 생성
- 주문 조회

### 포인트

- 포인트 추가
- 포인트 감소

## 3. 기능 요구사항

### 메뉴

- 커피 메뉴 목록을 조회할 수 있다.
- 메뉴에는 다음 정보를 포함한다.
    - 메뉴 ID
    - 메뉴 이름
    - 가격

### 주문 생성

- 사용자 식별값과 메뉴 ID를 입력받아 커피를 주문할 수 있다.
- 주문 시 해당 메뉴의 가격을 기준으로 결제 금액을 결정한다.

### 포인트

- 사용자 식별값과 충전 금액을 입력받아 포인트를 충전한다.
- 충전 금액과 포인트는 1원 = 1P로 계산한다.
- 충전 금액은 0원보다 커야 한다.

### 결제

- 결제 수단은 포인트로 제한한다.
- 사용자의 포인트 잔액에서 주문 금액을 차감한다.
- 포인트 잔액이 주문 금액보다 부족한 경우 결제할 수 없다.

### 주문 데이터 전송

- 결제가 완료된 주문 정보를 데이터 수집 플랫폼으로 전송한다.
- 다음 정보를 전송한다.
  - 사용자 식별값
  - 메뉴 ID
  - 결제 금액
- 외부 데이터 수집 플랫폼은 Mock API 또는 테스트 코드로 대체할 수 있다.

### 인기 메뉴

- 최근 7일간 주문 데이터를 기준으로 인기 메뉴를 조회한다
- 주문 횟수가 많은 메뉴 3개를 조회한다.
- 메뉴별 주문 횟수가 정확하게 집계되어야 한다.
- 다수의 서버에서 동시에 주문이 발생하더라도 주문 횟수의 정합성을 보장해야 한다.

## 4. 비기능 요구사항

- 최근 7일간 결제 완료된 주문을 기준으로 메뉴별 판매 수량을 누락 또는 중복 없이 정확하게 집계해야 한다.
- 애플리케이션이 다수의 서버 인스턴스로 구성된 환경에서도 포인트 충전·차감, 주문·결제 및 인기 메뉴 집계의 정합성이 유지되어야 한다.
- 동시에 발생하는 요청에서도 데이터 정합성이 유지되어야 한다.
- 주문 및 결제 과정에서 오류가 발생한 경우 부분적으로 처리된 데이터가 남지 않아야 한다.
- 외부 데이터 수집 플랫폼의 일시적인 장애가 주문 및 결제 데이터의 정합성에 영향을 주지 않아야 한다.
